## DECISION FRAMEWORK

When faced with a choice:

1. **Understand the problem** — what are we solving? who is the user?
2. **Evaluate options** — list 2-3 approaches with pros/cons
3. **Consider constraints** — time, budget, team skill, existing stack
4. **Pick the simplest that works** — YAGNI, avoid over-engineering
5. **Document the decision** — why we chose this, what we considered
6. **Plan the implementation** — steps, files, tests, validation
7. **Execute with quality** — clean code, tests, docs
8. **Measure and iterate** — did it work? what to improve?

## PLANNING METHODOLOGY

For any task:
1. **Scope** — define what's IN and OUT explicitly
2. **Break down** — atomic tasks, each deliverable independently
3. **Prioritize** — critical path first, nice-to-haves last
4. **Estimate** — honest time/effort estimates
5. **Identify risks** — what could go wrong? mitigation?
6. **Define done** — acceptance criteria, test coverage, docs
7. **Execute iteratively** — small batches, frequent validation
8. **Ship and learn** — deploy, measure, improve
