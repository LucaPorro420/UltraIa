# 3. El corazón: `MediaField`

Este es el primer componente que deberíamos implementar.

No queremos que cada módulo intercambie prompts arbitrarios.

Todos deben hablar un lenguaje común.

Por ejemplo:

```json
{
  "world_id": "world_001",
  "time": 0,
  "environment": {},
  "entities": [],
  "relations": [],
  "events": [],
  "camera": {},
  "audio": {},
  "style": {},
  "constraints": {},
  "metadata": {}
}
```

Pero conceptualmente esto es mucho más que JSON.

JSON será solamente la **serialización**.

Internamente:

```text
MediaField
    │
    ├── Semantic State
    ├── Spatial State
    ├── Temporal State
    ├── Causal State
    ├── Acoustic State
    ├── Visual State
    └── Style State
```

# 4. Entidades

Cada objeto del mundo debe tener identidad persistente.

Ejemplo:

```json
{
  "id": "character_001",
  "type": "character",
  "identity": {
    "name": "Elena",
    "age": 28
  },
  "appearance": {},
  "personality": {},
  "voice": {},
  "position": [0, 0, 0],
  "rotation": [0, 0, 0],
  "state": {
    "emotion": "sad",
    "activity": "walking"
  }
}
```

El punto importante es:

```text
character_001
```

debe seguir siendo **el mismo objeto** durante toda la producción.

---

# 5. Relaciones

Las entidades no existen aisladas.

```json
{
  "source": "character_001",
  "relation": "holding",
  "target": "umbrella_001"
}
```

Otro ejemplo:

```json
{
  "source": "motorcycle_001",
  "relation": "passing_near",
  "target": "character_001"
}
```

Esto crea el:

# **World Graph**

```text
Elena
 │
 ├── holding ──► umbrella
 │
 ├── walking ──► street
 │
 └── observing ──► motorcycle
```

---

# 6. Eventos

Los acontecimientos deben ser entidades de primera clase.

```json
{
  "id": "event_001",
  "type": "motorcycle_pass",
  "start": 4.7,
  "duration": 1.8,
  "actors": [
    "motorcycle_001"
  ],
  "targets": [
    "character_001"
  ],
  "effects": [
    "engine_sound",
    "motion",
    "doppler",
    "shadow_change"
  ]
}
```

Esto permitirá que un único evento genere consecuencias en **varias modalidades**.

# 8. `World State`

El estado del mundo será dinámico.

Formalmente:

[
W_{t+1}=F(W_t,E_t,A_t)
]

donde:

* (W_t): mundo actual;
* (E_t): eventos;
* (A_t): acciones;
* (F): transición de estado.

Ejemplo:

```text
W0
 ↓
person walking
 ↓
EVENT: motorcycle passes
 ↓
W1
 ↓
character reacts
 ↓
W2
```

Esto será la base de la coherencia temporal.

# 11. Contrato del generador

Ejemplo conceptual:

```python
result = generator.generate(
    media_field=field,
    constraints=constraints,
    quality="high"
)
```

Resultado:

```python
GenerationResult(
    artifact=...,
    metadata=...,
    confidence=...,
    provenance=...
)
```

Esto permitirá posteriormente reemplazar un backend experimental por el modelo OMAG propio.

# 37. MVP realista

El primer objetivo **no** debería ser:

> “Generar una película completa”.

Debe ser:

> **Generar una escena de 5–10 segundos con una entidad persistente, movimiento, sonido sincronizado y capacidad de regeneración automática.**

Por ejemplo:

```text
Prompt:

"Una mujer camina por una calle lluviosa.
Una motocicleta pasa detrás de ella."
```

OMAG debe producir:

```text
WORLD
 ├── woman
 ├── motorcycle
 ├── street
 └── rain

TIMELINE
 ├── walking
 ├── rain
 └── motorcycle_pass

IMAGE
VIDEO
AUDIO
```

Después:

```text
Critic:
motorcycle sound 0.4 sec late

Correction:
temporal alignment

Regenerate
```

Ese sería un **MVP científico realmente valioso**.

# 38. La primera prueba de inteligencia del sistema

No evaluaría solamente:

> “¿el vídeo es bonito?”

Haría pruebas causales.

### Test A

Eliminar una entidad:

```text
motorcycle = removed
```

El sistema debería eliminar:

```text
motorcycle visual
motorcycle audio
shadow
doppler
interaction
```

---

### Test B

Mover la motocicleta.

Debería cambiar:

```text
visual trajectory
audio timing
doppler
shadow
```

---

### Test C

Cambiar lluvia por nieve.

Debería cambiar:

```text
visual particles
surface
lighting
sound
character clothing
movement
```

Esto demostraría que OMAG **entiende una representación común**, en lugar de simplemente producir tres outputs independientes.

# 39. El experimento científico central

La prueba definitiva sería:

```text
WORLD A
 ↓
IMAGE
AUDIO
VIDEO
```

Después modificar:

```text
WORLD A → WORLD B
```

sin volver a describir el prompt.

Y comprobar si:

```text
IMAGE B
AUDIO B
VIDEO B
```

cambian coherentemente.

Si esto funciona, tenemos evidencia de que:

> **MediaField realmente está funcionando como representación generativa multimodal.**

# 40. Fase 2 → Fase 3

Con esto ya tenemos definida la arquitectura de implementación.

La **Fase 3** debería ser mucho más práctica:

```text
FASE 3
│
├── crear repositorio OMAG
├── crear MediaField Schema
├── implementar World Graph
├── implementar Entity System
├── implementar Event System
├── implementar Timeline
├── implementar Memory
├── implementar Generator Interface
├── crear ComfyUI Adapter
├── crear Blender Adapter
├── crear Open-Sora Adapter
├── crear Critic Interface
├── crear Orchestrator
├── crear API
├── crear CLI
├── crear tests
└── ejecutar primer experimento
```

Y aquí hay una decisión arquitectónica importante: **yo empezaría la Fase 3 por el `MediaField Schema` y el `World Engine`, no por el modelo neuronal**. Eso nos permite construir primero el “sistema operativo” sobre el que después podremos entrenar el verdadero **OMAG World Model** sin tener que rehacer toda la plataforma.
